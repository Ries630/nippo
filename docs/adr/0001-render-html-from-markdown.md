# ADR-0001: Markdownから自己完結HTMLを生成する

- ステータス: 承認済み
- 日付: 2026-09-01
- 関連: [Issue #5](https://github.com/Ries630/nippo/issues/5)

## 背景

`trend`、`insight`、`review` は、Claude Code または Codex の skill が収集結果を分析し、Markdown レポートとして保存する。既存の Markdown パスは利用者の運用との互換性のため維持しながら、同じ内容をグラフィカルに読める自己完結 HTML も必要になった。

skill に Markdown と HTML を独立して生成させると、同じ収集結果から文章、数値、判断が異なる可能性がある。一方、HTML を正にして Markdown を逆生成すると、従来の Markdown 出力を安定して維持しにくい。

## 決定

skill は従来どおり Markdown を先に生成し、保存済み Markdown を Rust の決定論的レンダラーへ渡して、同じ stem の HTML を生成する。

HTML は本文、表、視覚化を一つのファイルに含め、外部 CSS、JavaScript、画像、CDN に依存しない。視覚化は Markdown に存在する値と構造だけから作り、新しい分析、数値、判断を追加しない。HTML の書き込みに失敗した場合は完成済み Markdown を保持し、不完全な HTML は残さない。

具体的な生成順序、対象モード、視覚化、安全性の規範は
[HTML レポート契約](../html-reports.md) を正とする。

## 検討した代替

- skill が Markdown と HTML を別々に生成する: 実装量は少ないが、文章と数値の不一致を機械的に防げないため採用しない。
- HTML を正として Markdown を生成する: HTML 単体の表現力は高いが、既存の Markdown 出力との互換性を守りにくいため採用しない。
- 構造化された共通レポートモデルから Markdown と HTML を生成する: 二形式の一致をより厳密に保証できるが、現在 skill が担う自由記述の分析までモデル化する必要があり、3 モードへの HTML 追加を超える再設計になるため採用しない。

## 受け入れた代償

- レンダラーは対象モードの見出しと表構造に依存するため、テンプレート変更時にレンダリングテストも更新する必要がある。
- 同じレポートを二形式で保存するため、保存容量と検証対象が増える。
- HTML の視覚化は Markdown に含まれる情報へ限定される。

## 再評価の条件

- テンプレート変更のたびにモード固有パーサーが繰り返し壊れる場合
- HTML 以外にも同じ内容の出力形式を追加する場合
- skill が安定した構造化レポートモデルを出力できるようになった場合
